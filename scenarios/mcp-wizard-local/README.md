# Scenario: MCP Wizard generated server, local ($0)

Probes the JWT checks of a server generated by
[mcp-wizard-generators](https://pypi.org/project/mcp-wizard-generators/) with every provider
shape, using the in-process mock issuer. No Docker and no cloud: the generated server
accepts an `http://` discovery URL on loopback.

```bash
# 1. Generate a docker + jwt project (any discovery URL: run.py overrides it).
python -m venv gen && gen/bin/pip install "mcp-wizard-generators>=0.6,<0.7"
#    then call generate_python_mcp(..., deployment=DeploymentConfig(target="docker",
#    inbound_auth=InboundAuthConfig(mode="jwt", discovery_url=..., allowed_audiences=...)))
# 2. Install it into its own environment.
python -m venv srv && srv/bin/pip install -e ./work/project
# 3. Probe.
python scenarios/mcp-wizard-local/run.py ./work/project srv/bin/python --port 8765
```

Each shape's well-formed token is expected to get what the `mcp-wizard-0.6` model predicts
(with `aud=api://mcp`, `scope=mcp.read` required):

- auth0, okta: 200;
- cognito: 401 (no `aud`);
- entra: 403 (`roles`, not `scp`);
- keycloak: 200 (`aud` from the audience mapper).

Last run (2026-11-22, generators 0.6.0): all cases matched.
